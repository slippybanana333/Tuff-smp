# Tuff SMP - Mod Knowledge Base

Everything about how this project works. `CLAUDE.md` is the short operating manual; this file is the reference. **Update it whenever anything changes.**

Mod id `shrinecraft` - display name "Tuff SMP" - command root `/tuffsmp` (was `/shrinecraft`; ids/namespace/config folder unchanged) - Minecraft 1.21.11 - Fabric (Yarn mappings, Java 21).
Versions: Yarn `1.21.11+build.6`, Fabric Loader `0.20.1`, Fabric API `0.141.6+1.21.11`, Fabric Loom `1.14.10`, Gradle `9.2.1`.

---------------------------------------------------------------------------------------------------------------------------------------------
## 1. What the mod does (plain English)
* 14 legendary items, every one **unbreakable**, every one with a hand-made **3D model** used in the hand, on the ground, in item frames and in inventory slots.
* A **Shrine** block. An admin assigns one of the 14 rewards to it; a player who brings the materials sneaks + right-clicks it and receives the item. Then the Shrine is used up forever.
* **Five inventory background themes** (ocean, lava, sculk, arctic, end) chosen with the client command `/tuffsmp gui <ocean|lava|sculk|arctic|end|auto|off>` (`/gui ...` still works as a short alias).
* Worn-armor visuals (helmet, chestplate, leggings, boots) and a cape.
* A set of **tools** (Python/JS) that generate models/textures and a **standalone 3D viewer** (`viewer/index.html`) to inspect everything without Blockbench or Minecraft.

## 3. The Shrine (block `shrinecraft:shrine`)
Files: `shrine/ShrineBlock`, `ShrineBlockEntity`, `ShrineState`, `ShrineInteraction`, `ShrineMenu`, `ShrineRecipe`, `ShrineRecipes`; client `render/ShrineBlockEntityRenderer`.
* **State lives in the block entity** (`Recipe` string + `Claimed` boolean + `ClaimedBy` uuid -> saved with the world, so a claimed Shrine stays claimed across restarts). The block state property `state` mirrors it (models, light, particles).
* Unbreakable in survival (hardness -1, blast-proof) on purpose: otherwise players could break + re-place it to reset a used Shrine. Creative operators can remove it.
* **UNCONFIGURED** - an admin (permission level 2+, `DefaultPermissions.GAMEMASTERS`) sneak + right-click with an **empty main hand** opens a chest-style window (server-side GUI, no client code) listing all 14 rewards as real 3D items; clicking one assigns it. Purple portal particles.
* **CONFIGURED** - right-click lists the required materials in chat (green tick = have enough, red cross = short, with have/need); a rotating, bobbing 3D preview of the reward floats above the block. Sneak + right-click: if everything is there it consumes exactly the recipe, gives the item, and the block becomes CLAIMED; otherwise it prints the list with missing items highlighted and takes nothing. Enchanting-glyph particles.
* **CLAIMED** - any right-click says "already used". Ash particles. Never grants again.
* `ShrineBlock.onUse(...)` is the required override. Because vanilla skips `onUse` when you sneak with items in hand, `ShrineInteraction` also registers Fabric's `UseBlockCallback` for that case (both call the same `handleUse`).
* Materials are counted in the 36 main slots + offhand (not armor slots).
* **Recipes** (one central registry): `ShrineRecipes.defaults()` (id, display name, ingredient list, output factory, placeholder flag). On first run `config/shrinecraft/shrine_recipes.json` is written; edit it (name/ingredients/placeholder, ids fixed) and run `/tuffsmp reload`. The file wins over the defaults. An **empty ingredient list = not set up = cannot be crafted** (the Shrine says so).
  Recipes 1-3 and 5-12 are exactly as specified. **#4 Frost Longbow has a clearly marked STAND-IN recipe** (Bow, 64 Blue Ice, 64 Packed Ice, 32 Snow Block, 16 Diamond) flagged `placeholder`; **#13 Strange Cape and #14 Silver's Spawn Orb are empty placeholders**.
* Admin commands (`/tuffsmp ...`, level 2): `recipes`, `reload`, `reset <pos>` (un-claim/un-configure), `give <player> <recipe_id>` (fully enchanted), `selftest`.

## 5. Client features (`src/client/...`)
* **/tuffsmp gui** (`client/gui`, alias `/gui`): `off` (default, vanilla) | `ocean|lava|sculk|arctic|end` (lock to that biome theme). `/tuffsmp gui ...` is caught as typed text by `ClientSendMessageEvents.ALLOW_COMMAND` (NOT a brigadier client command: a client root named `shrinecraft` would hide the server's give/essence/reload). The server command also lists `gui` only for tab-completion. Works for non-ops. Verified in the real client by gametest step `gui command` (TUFF_ONLY="gui command"): all words work and `/tuffsmp essence` still reaches the server. Saved in `config/shrinecraft_gui.json` (per player/install). The five panels are normal bundled PNGs (`textures/gui/backgrounds/*.png`, painted on the vanilla inventory panel, same layout) preloaded **once at startup** (`GuiBackgrounds.preload`) - switching only changes which texture id is drawn (`InventoryScreenMixin` swaps the texture argument of `InventoryScreen.drawBackground`). Never reloads resources.
  **The zone-following `auto`/`dynamic` mode is REMOVED** (owner request, "completely remove GUI auto"): `ZoneDetector`, `config/shrinecraft/zones.json`, `zones_mask.png`, the `/gui where|reload|mark|unmark|islands|map` words and the two zone gametest steps are gone; an old `shrinecraft_gui.json` saved with mode "dynamic" now loads as `off`. The theme is simply OFF or one locked biome theme.
* **Armor extras** (`client/render/ArmorExtras*`): vanilla armor boxes cannot show a slouchy helmet, chestplate lapels/back collar, baggy leg bulk or shoe tongues, so those are extra boxes defined in `assets/shrinecraft/armor_extras/tuff_extras.json` (read by the game and by the viewer) and drawn by a Fabric `LivingEntityFeatureRendererRegistrationCallback` renderer on **players** (posed by running the real player model animation). Armor stands/mobs wearing the pieces show the vanilla-box version only.
* **Cloud Lance HUD**, **Shrine preview renderer** (modelled on vanilla's Vault renderer; tweak constants at the top of the class).
* The cape renders through the vanilla `wings` equipment layer (the elytra model) with a cape-like texture. A true separate cape model was not added; see Assumptions.

## 6. The art pipeline (`tools/`)
**Models** are JSON block models with **named elements** (cuboids). Conventions: +Y = business end, centred on x=8/z=8, detailed front = south (+Z), every held item has an element called `grip`, coordinates stay inside -16..32 (Minecraft refuses to load models outside that). Models have `display` transforms for third person, first person, gui, ground, fixed, head, on_shelf (left hand is auto-mirrored by the game). `item/*.json` in `assets/shrinecraft/items/` are the 1.21.4+ item model definitions (bow and crossbow switch models for draw / charged states).

| Tool | What it does |
|---|---|
| `gen_models.py` + `modelspec.py` | Scaffold: element specs -> model JSON, UV layout, display transforms, item definitions, block state, equipment assets. Refuses to overwrite without `--force`; `--only <model>` regenerates a single model (used for the Sculk Mace war-hammer redesign). |
| `retune_display.py` | Recomputes only the `display` blocks of existing models (first-person grip/centre pin + visible-fraction fit, third person, GUI, ground, frame, head); bow variants copy the base's display; bow is turned a quarter turn (`BOW_FLAT_YAW`) so its broad side shows in frames/ground. |
| `viewer_oneshot.js` | Renders one viewer view to a PNG. In-game test: `TUFF_ONLY` env var filters steps; the hand step waits 45 ticks (vanilla keeps a freshly swapped item lowered until the attack cooldown recharges); frame close-ups use invisible frames (software GL hides thin items behind the frame plate). |
| `relayout_uv.py` / `uvlayout.py` | recompute UVs from current element sizes (1 texel per model unit, power-of-two atlases, 1px gutter) |
| `paint_textures.py` + `paintlib.py` | pixel-art painter. Each texel is evaluated at its real 3D position by the element's material (`tools/model_materials.json`: element -> material; unknown element names fall back by name prefix, then to the model default). Also paints armor layers (vanilla 64x32 armor UV layout), the cape wing texture, the extras texture, the 5 GUI backgrounds. |
| `check_models.py` | vanilla loader rules, texture/UV consistency, hand size per item kind (player 32 units, arm 12), grip within 1.5 units of the palm (third person) / 2 (first person), gui/ground/frame fit, supporting files, tag-file existence. Exit 1 on any failure. |
| `export_bbmodel.py` | `blockbench/*.bbmodel` generated from the JSON (best effort, could not be opened in Blockbench here) |
| `build_viewer.py` + `viewer_app.js` + `viewer_template.html` + `vendor/three.min.js` (r147) | builds `viewer/index.html`, one self-contained offline file |
| `viewer_screenshots.js`, `viewer_oneshot.js` | Playwright screenshots of the viewer |
| `rebuild_all.py` | relayout -> paint -> check -> bbmodel -> viewer (`--jar`, `--shots`) |
| `server_selftest.sh` | headless server + `/tuffsmp selftest` |

**Viewer**: list of the 14 items + Shrine (with states), mannequin at vanilla Steve proportions (drawn at the real in-game 0.9375 entity scale), contexts (Model inspect / Inventory gui / Ground / Item frame / First person in a 16:9 frame / Third person right hand) using the same transform chain as the game, armor worn with vanilla armor geometry (outer 1.0 inflate, leggings 0.5/0.4, boots 0.9, hat shell 1.5) + the extra geometry toggle + the cape, toggle per piece + "Wear all four", orbit/zoom/pan, 16-unit grid + block/32-unit player height reference, Textures/Flat/Wireframe, click an element to see its name/from/to/size/rotation, and a size-comparison mode (items at their real held size beside the mannequin).
The hand math in the viewer was checked against real in-game screenshots (see Testing).

## 7. Verified facts about 1.21.11 (read from the decompiled sources - useful when something breaks)
* Items need `Item.Settings.registryKey(...)` before construction. Swords/tools/spears/armor are plain `Item`s configured through `Item.Settings.sword/pickaxe/axe/spear/armor(...)`.
* Spear = components `kinetic_weapon`, `piercing_weapon`, `attack_range`, `swing_animation`, `use_effects`, `weapon`, `damage_type`; its right-click default starts the charge (`Item.use`).
* Block: `onUse(BlockState, World, BlockPos, PlayerEntity, BlockHitResult)`; `onUseWithItem` is separate; vanilla skips both when sneaking with an item in either hand.
* Block entities save with `readData(ReadView)` / `writeData(WriteView)`.
* Permissions: `player.getPermissions().hasPermission(DefaultPermissions.GAMEMASTERS)`; commands: `CommandManager.requirePermissionLevel(CommandManager.GAMEMASTERS_CHECK)`.
* Ammo use is an enchantment effect (`minecraft:ammo_use`); riptide strength is `trident_spin_attack_strength` = 1.5 + 0.75*(level-1).
* Fabric API has no "modify damage" event; true damage is done by changing the arrow's `DamageSource` (mixin on `DamageSources.arrow`).
* `Entity.slowMovement` (cobweb, berries) and `Entity.getVelocityMultiplier` (soul sand, honey) are the slowing hooks.
* Equipment attribute modifiers (armor points) only apply after an entity has ticked once - relevant for tests.
* Model JSON: element `rotation` accepts any angle (axis+angle or x/y/z); coordinates must be -16..32; display translation is clamped to +-80, scale to <= 4; the left-hand display is the right-hand one mirrored automatically.
* Item frame: the visible face for `fixed` rotation [0,0,0] is the model's NORTH face, with [0,180,0] the SOUTH face.

## 9. Assumptions and interpretations (so you can overrule them)
1. "Strength 2", "Speed 3" etc. = the Roman-numeral level (Strength II = amplifier 1). Same-effect overlap uses the highest level, never added.
2. Cutlass "every other vanilla enchantment": all that make sense on a sword and can coexist - Sharpness 5, Looting 6, Sweeping Edge 3, Unbreaking 3, Mending, Efficiency 5, Fortune 3 (Smite/Bane conflict with Sharpness, Silk Touch with Fortune, curses skipped).
3. Sculk Mace tier ladder is the owner's explicit one (2026-11-15): t1 Density I, t2 Density II, t3 Wind Burst I, t4 Density III, t5 Wind Burst II + the wave unlock (each tier is the COMPLETE set; Density + Wind Burst never coexist now). Sculk Wave is a RADIAL blast from the hit target (owner: "want a radial blast instead"), radius `WAVE_RADIUS`=4 blocks is my pick (TWEAK ME). Wave/cooldown: the cooldown starts when the ability turns on and lasts duration + stated cooldown, i.e. 45 s counted after the buff ends (Cutlass and Mace). Lava Bomb: cooldown starts at arming (as specified).
4. Armor enchants: Protection IV + Unbreaking III + Mending + piece-specific maxima; boots take Depth Strider (Frost Walker cannot coexist), no Thorns, no curses.
5. Frost Longbow "true damage" = bypasses armor and armor toughness (the vanilla `bypasses_armor` tag); enchantments and effects still apply.
6. Sculk Cannon: "swap hands flips the mode" = when the cannon moves from main hand to offhand. Mode 1 accepts only plain `minecraft:arrow`; mode 2 any arrow. An arrow must still be in the inventory (like vanilla Infinity) but none is consumed.
7. Silver: base stats = the average vanilla horse (speed 0.225, jump 0.7, health 22.5) x1.5. Gets a saddle so it is rideable. If Silver dies while the owner is online the orb goes on cooldown; if the owner is offline the orb reports Silver as not nearby.
8. Shrine: unbreakable in survival; items counted in main inventory + offhand; admin check = permission level 2 (a console/command-block cannot use the GUI).
9. The 14 items are also shown in the creative tab (`ModItemGroups.SHOW_ITEMS_IN_CREATIVE_TAB`) for testing.
10. Looks not specified: **Boots** = white high-top boots with a navy collar/heel/toe cap, thick white sole with a blue "air" window, yellow lightning bolt on both sides, neon-orange tongue and white laces. **Harbinger** = blackened iron pickaxe with bone-white plates, a skull-like hub with glowing crimson eyes, curved glowing-tipped picks and a bone-wrapped haft. **Anaklusmos** = sea-bronze trident with teal patina, wave-pattern wrapped grip and a sea-blue gem. **Strange Cape** = deep-violet star-flecked cloak with a ragged asymmetric hem and a slit. **Sculk Cannon** = near-black body with teal veins and sensor clusters. **Silver's Orb** = frosty ice-blue voxel orb with a deep-blue horse-head silhouette on both faces.
11. Models are low-poly cuboid art at vanilla pixel density; "glow" is bright pixels (items cannot truly emit light), plus particles where the brief asks.
12. The cape is rendered through the elytra wings layer (cape-like texture); the wings spread when gliding like vanilla. No separate cape model.
13. Frost Longbow translucency is approximated with a pale opaque ice palette (translucent pixels in item textures render unreliably).
