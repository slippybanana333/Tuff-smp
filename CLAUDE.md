## What this is
A Fabric mod (Yarn mappings, Java 21) with **14 3D items (13 built from the owner's icons, the Sculk Mace hand-built) + one block (the Shrine)**. The mod id is `shrinecraft`; items are `shrinecraft:<snake_case_name>`. The COMMAND root is `/tuffsmp` (`/tuffsmp reload|give|essence|selftest|trust|gui` (trust + gui = everyone, the rest op level 2), short forms ONLY `/trust` `/gui` `/essence` (no /tuff, /tuffgive, /tuffreload); the old `recipes` and `reset` commands were REMOVED), renamed from `/shrinecraft`; the mod id, namespace, asset/data folders, and `config/shrinecraft/` stay `shrinecraft` on purpose (the Java package is `dev.tuffsmp.shrinecraft`) (changing them would break saves, the resource pack and the owner's config).
The Shrine is the *only* way to obtain the items in survival. The owner is **not a programmer**: explain results in plain English, make sensible choices instead of
asking, and list every assumption in your final report.

Versions (verified): Minecraft 1.21.11, Yarn `1.21.11+build.6`, Fabric Loader 0.20.1, Fabric API `0.141.6+1.21.11`, Loom 1.14.10, Gradle 9.2.1 (wrapper), Java 21.

## Golden rules (from the brief - do not break them)
1. Every item is **unbreakable** (`DataComponentTypes.UNBREAKABLE`).
2. Every item uses its **full 3D model in ALL display contexts** (hand, ground, frame, inventory/GUI): one model per item, display transforms for every context. Never a flat 2D icon. **ONE OWNER-APPROVED EXCEPTION: the four armor ITEMS (`shrine_helmet/chestplate/leggings/boots`) are flat 2D sprites** (vanilla `item/generated`, texture = the 32x32 icon) in inventory, hand, ground and frames - owner request. The armor WORN on the body is unchanged (3D netherite shape, polished-tuff texture). Flagged `"flat": true` in `tools/model_materials.json`; `check_models.py` / `build_viewer.py` handle them; they were removed from `sprite_extrude.py` CONFIG so nobody re-extrudes them.
3. Every number (cooldown, duration, damage, chance, multiplier) is a **commented constant at the top of that item's class**.
4. Bugs hit before - never repeat them:
   * Shrine right-click overrides `onUse(BlockState, World, BlockPos, PlayerEntity, BlockHitResult)`. `onUseWithoutItem` does not exist in 1.21.11 Yarn.
     (Sneak + items in hand never reaches `onUse` in vanilla, so `ShrineInteraction` also hooks Fabric's `UseBlockCallback`.)
   * Tool component rules that use block tags must use the **TagKey through `Registries.createEntryLookup(Registries.BLOCK).getOrThrow(tag)`** - never resolve tags into block lists in static init (crashes the server at startup). (The Cutlass no longer has a tool component - it is just a sword - but the rule still applies to any future tool item; vanilla-based examples: `TridentItem.createToolComponent()` in `AnaklusmosItem`.)
   * Silver's orb: write its state ONLY through `SilversSpawnOrbItem.setData(...)` (it also sets the model flag that switches the 3D model between stored / released / cooldown).
   * If a custom enchantment's `supported_items` is a tag, that tag file must exist at `data/shrinecraft/tags/item/<name>.json` (`check_models.py` verifies this).
5. The JSON model files in `src/main/resources/assets/shrinecraft/models` are the **single source of truth** for geometry. Textures are generated from them by script - EXCEPT the 13 icon-based items (everything but the Sculk Mace): the owner's 32x32 icons in `tools/reference/icons/` ARE the textures and `tools/sprite_extrude.py` builds their 3D models from them (see below).

## Display Editor (positions of items in hand / inventory / frame / ground)
`viewer/index.html` (standalone, double-click) and the published artifact page are a LIVE editor: sliders for rotate X/Y/Z, move X/Y/Z and scale for First person, Third person, Inventory, Ground and Item frame, a vanilla reference item (Ours / Vanilla / Both side by side, real vanilla hand positions from the jar - `tools/make_vanilla_refs.py`), and "Copy changes" which produces JSON (`tuffsmp-display-v1`). The owner pastes that JSON in chat (or uploads it); apply it with `python3 tools/apply_display.py changes.json`, then `python3 tools/rebuild_all.py --jar`. Applied positions are stored in `tools/display_overrides.json`, which `gen_models.py` / `retune_display.py` re-apply, so a rebuild never loses them. SAVING WITHOUT COPY/PASTE: the published artifact (https://claude.ai/artifact/5w1rwoQQWRDVgczbJjU4cQ, capabilities db + downloads) autosaves the owner's changes to the shared document `display/pending` (format tuffsmp-display-v1: models -> key -> rotation/translation/scale; plus savedAt, count). When the owner says "apply my changes": (1) ArtifactData get collection `display` doc `pending` with out_dir to save it as JSON, (2) `python3 tools/apply_display.py <that file>`, (3) `python3 tools/rebuild_all.py --jar`, (4) `python3 tools/build_viewer.py` and republish `viewer/display_editor_artifact.html` (same file path) so the page's baseline matches the mod, (5) ArtifactData set `display/pending` to {format, models:{}, appliedAt} (needs if_version). Rebuild the page with `python3 tools/build_viewer.py` (also writes `viewer/display_editor_artifact.html`, the body published as the artifact).

## Worn pieces (cape + armor) placement
The Display Editor also edits how each WORN piece sits on the player: select a piece under "Wear on the mannequin" and the sliders switch to "Worn: <piece>" (the held item stays on the mannequin and its own settings are kept; click the "Held: ..." button to go back). Values live in `src/main/resources/assets/shrinecraft/worn_display.json` (per piece: pivot, translation, rotation, scale in player MODEL space: x = player's left, y = DOWN, z = BACK; the editor shows up/forward as +). The game applies them: `client/render/WornDisplay.java` (reads the file, re-checks every 3 s) + mixins `ElytraFeatureRendererMixin` (the cape) and `ArmorFeatureRendererMixin` (armor layers), and `ArmorExtrasFeatureRenderer` (one extras model per piece). The editor's saved JSON has an extra `"worn": {piece: {translation, rotation, scale}}` block; `tools/apply_display.py` writes it into worn_display.json. Identity entries cost nothing and draw vanilla. (OBSOLETE for the armor since the polished-tuff change: the armor has no extra parts any more, so the part bar stays hidden; the whole-piece sliders still work and the code is kept.) PER-PART editing (kept for future extras): the armor was built from named parts (helmet: forehead gem, crystal crown; chestplate: chest crystal, back plate + spine crystals, shoulders (cap + gem); leggings: belt gem + rear tasset, knee gems; boots: toe gem + heel plate; helmet also has a neck guard. The crack shells are group `cracks`, hidden from the part bar). In worn mode the editor shows a part bar (Whole piece / each part); a part gets Move X/Y/Z + Width/Height/Depth (stored as `worn[piece].groups[name] = {translation, scale}` and written by `apply_display.py` to the `groups` block of the piece in worn_display.json; applied in-game by `ArmorExtrasModel` via `WornDisplay.group`). On the arm parts a positive X = outward. The whole piece uses the normal worn sliders (Width/Height/Depth = scale X/Y/Z).

Its icon is drawn by `tools/make_essence_icon.py` (blue flame, the owner's reference minus the face) and extruded like the other icons (`sprite_extrude.py`, model `magic_essence`). Recipe ingredients can require a potion type (`"potion": "minecraft:strong_swiftness"`, used by Silver's Orb: 9 Swiftness II).
`SHRINE_RECIPES.md` lists every item's Shrine recipe (all 14 final, from the owner's edited file); `shrine_recipes.json` in the project root is the ready-to-edit copy of the config the game reads from `config/shrinecraft/shrine_recipes.json` (then `/tuffsmp reload`). Regenerate both from `run/config/shrinecraft/shrine_recipes.json` if recipes change in `ShrineRecipes.java` - and BUMP `ShrineRecipes.CONFIG_VERSION` (an older recipe config file is auto-replaced by the defaults, old one kept as `.old-vN`; without a bump the owners' old file keeps overriding the new defaults).

## The tweak workflow (what to do when the owner says "make the blade longer" or "change the cooldown")
| Request | What to do |
|---|---|
| Change a **shape** ("blade longer", "bigger head", "add a spike") | Edit the element **by name** in `assets/shrinecraft/models/item/<item>.json` (`from`/`to`/`rotation`; names like `blade`, `guard`, `grip`, `pommel`), or add an element with a similar name. Then `python3 tools/rebuild_all.py` (recomputes UVs, repaints textures, checks proportions, rebuilds the resource pack). Look at the in-game screenshots (see below). Keep the element named `grip` where the palm holds the item. Elements must stay within -16..32. |
| Change a **look/colour/pattern** | `tools/paintlib.py` (materials) and `tools/model_materials.json` (which element uses which material). Re-run `rebuild_all.py`. |
| Change a **number** (cooldown, damage, duration, chance...) | The `// TWEAK ME` constants at the top of the item class in `src/main/java/.../item/` (armor levels: `ability/ArmorEffects.java`). Rebuild the jar. Update the knowledge base if the default changed. |
| Change a **Shrine recipe** | Easiest: `config/shrinecraft/shrine_recipes.json` then `/tuffsmp reload`. Permanent default: `shrine/ShrineRecipes.java`. All recipes are final (none are placeholders any more). |
| Change **GUI zones** | `config/shrinecraft/zones.json` (centre, start angle, the five themes clockwise, hub / outer radii, `islands`) then `/tuffsmp gui reload`; mark islands in the game with `/tuffsmp gui mark <theme>`, see the result with `/tuffsmp gui map`; from a map picture with `tools/zones_from_map.py`; logic in `client/gui/ZoneDetector.java`. |
| Change **display transforms** (how it sits in the hand) | `display` block of the model json. Verify with `python3 tools/check_models.py` and the in-game screenshots (`TUFF_ONLY=mannequin` / hand steps). |
| Change the **armor look** | The armor is vanilla NETHERITE armor (shape, panels, layers) TEXTURED AS POLISHED TUFF, helmet with an open face (owner: "ditch this whole idea, make it look like netherite with the shape and layers but the actual texturing should look like polished tuff"). No glow, cracks, crystals or extra 3D parts any more. The look lives in `tools/tuffpal.py` (real `tools/reference/polished_tuff.png` tiled over the real netherite layer textures, shifted by the netherite shading; shading strength = the `5.0` in `polished_tuff`). Run `python3 tools/make_polished_tuff_armor.py` (empty extras json + the four item icons = the vanilla netherite icons recoloured), then `python3 tools/rebuild_all.py`. Open-face window: `paint_textures._tuff_layer(open_face=True)`. See MOD_KNOWLEDGE_BASE.md 'POLISHED TUFF NETHERITE'. |

**Icon-based items (all except the Sculk Mace)**: the owner drew a 32x32 icon per item; `python3 tools/sprite_extrude.py [names]` turns each icon into a 3D model (each opaque pixel becomes a column whose thickness follows a rounded profile; pixels of equal thickness are merged into boxes; FRONT = the icon, BACK = a darker designed view, every rim/side face gets its own texture strip built from the icon's own colours so all sides have a design - all packed in one atlas png; hands/frames use the VANILLA display sets: handheld / bow / crossbow / generated). To change a look, edit the icon png and re-run it (then `rebuild_all.py`). Thickness/size knobs are in `CONFIG` at the top of that script. These models are marked `"sprite": true` in `tools/model_materials.json`, so `relayout_uv.py`, `paint_textures.py`, `retune_display.py` and the palm/grip checks skip them. Draw/charge states of the bow and cannon are the same icon with a string + arrow / bolt drawn on (`draw_bow`, `draw_bolt`); the orb has three icons (stored/released/cooldown). Old hand-built models are kept in `tools/reference/old_handmade_models/`. Worn armor layers and the cape (`textures/entity/equipment`) are painted by `paint_textures.py` using colour pools sampled from the same icons (`paintlib._icon_materials`), so what you wear matches the icon colours (chestplate brown + purple/orange, leggings blue, helmet grey knit + beige runes, boots black/white, cape red + gold).
`tools/gen_models.py` is a **one-time scaffold**; it refuses to overwrite existing models without `--force` (which discards hand edits). Normal tweaks never need it.
`python3 tools/gen_models.py --only <model>` rebuilds just ONE model from `tools/modelspec.py` (hand edits to that model are discarded) - used for the Sculk Mace redesign (dwarven war-hammer look: double-drum head, wrapped haft, clawed pommel, sculk colours).
`python3 tools/retune_display.py [names]` recomputes only the `display` blocks (hand / frame / ground / head) after a geometry change, without touching the shapes. First-person fit rule: weapons are pinned by the grip to the palm, everything else is centred; at least ~62% (weapons) / 85% (others) of the item must be on screen. Vanilla-based items (sword, axe, pickaxe, spear, trident, bow, crossbow, mace) must keep the silhouette of their vanilla counterpart.
`python3 tools/set_cannon_ready.py --third "rot | trans | scale" --first "rot | trans | scale"` sets the hand pose of the Sculk Cannon's DRAWING + CHARGED states (pulling_0/1/2 and charged share one pose; writes the 4 model files AND `tools/display_overrides.json`). The gametest step `cannon aim` (`TUFF_ONLY="cannon aim"`) shoots vanilla charged crossbow vs charged cannon from above / the side / behind to check where the barrel points.
Hand size: `THIRD_SCALE` in gen_models.py (keep tools near vanilla size). Side-by-side vanilla comparison: `TUFF_ONLY=mannequin`.
Per-item screenshot sheets from the real game (current, non-armor): run the gametest steps `model views`, `ground close`, `hand ,gui zoom`, `frame closeups,orb states,cannon states` (each with `TUFF_MODEL=<comma list of item ids>`; separate runs, copy the screenshots into one folder) then `python3 tools/make_model_sheets.py <folder>` -> `screenshots/models/<item>.png`. (`make_context_sheets.py` is the older armor-inclusive version.)
In-game screenshot test filter: `TUFF_ONLY="sculk_mace,ground" ... ./gradlew runClientGameTest`. One-off viewer render: `node tools/viewer_oneshot.js out.png '{"item":"sculk_mace","ctx":"first|third|fixed|ground|gui|model"}'`.
